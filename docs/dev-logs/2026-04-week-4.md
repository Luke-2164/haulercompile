## Technical decisions
- I separated the public repository from the private implementation repository
- I kept the public repository focused on generalized documentation and Dev Logs
- I used Supabase as the initial backend foundation for authentication and database work
- I used a publishable key for the frontend connection test
- I avoided using a service role key for frontend testing
- I decided to keep the first version simple and avoid adding unnecessary infrastructure too early

## Problems and fixes
### Problem: Next.js could not read the Supabase environment variables
- What I tried: Checked the environment variable names and the app directory structure
- Fix: Moved `.env.local` into the frontend app directory
- Current status: The app can now read the required Supabase environment variables

### Problem: PowerShell blocked `npm run dev`
- What I tried: Checked the error message and PowerShell execution policy
- Fix: Adjusted the execution policy for the current development session
- Current status: The Next.js development server runs locally

### Problem: Hydration mismatch warning in the browser
- What I tried: Tested the same page in a private browser window
- Result: The warning disappeared in private mode
- Current status: The issue was likely caused by a browser extension, not the app code
